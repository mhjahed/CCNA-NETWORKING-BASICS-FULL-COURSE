Lab 1 · Configure a Wireless Router and ClientsRehearse in simulatorPT activity

Scenario: help Natsumi connect her new home — coax + splitter + modem + TV, two wired PCs, one wireless laptop. Configure the router GUI (defaults admin/admin), a secure WLAN, DHCP clients, then verify internet via skillsforall.srv.

  • Part 1 · Coaxial: Splitter Coaxial1 → Cable Modem Port 0; Splitter Coaxial2 → TV Port 0; turn the TV ON (picture appears).
  • Part 1 · Copper straight-through: Modem Port 1 → router Internet port; Office PC FE0 → router GE1; Bedroom PC → GE2.
  • Part 2 · Office PC → IP Configuration → DHCP; note the default gateway (the router, 192.168.0.1); browse to it and log in admin / admin.
  • Part 2 · Setup tab: Maximum Number of Users = 10 → Save Settings (reconnect if dropped).
  • Part 2 · Administration tab: new password MyPassword1! → Save → re-login with the new password.
  • Part 2 · Wireless tab: Enable 2.4 GHz, SSID MyHome → Save. Wireless Security: WPA2 Personal, passphrase MyPassPhrase1! → Save.
  • Part 3 · Laptop → PC Wireless → Connect to MyHome with the passphrase; Link Information shows success; verify a 192.168.0.x lease.
  • Part 3 · Browse skillsforall.srv from Laptop, Office PC and (after DHCP) Bedroom PC — all load.
Model answers & gotchas
  • Default gateway / router address: 192.168.0.1; DHCP clients receive 192.168.0.100 upwards.
  • After saving the router IP / DHCP changes you can lose the GUI session — toggle the PC Static→DHCP to renew, then re-open the browser.
  • Default passwords must be changed immediately in real life; they are public knowledge (including to threat actors).
  • WPA2 Personal is the strongest option on this router; SSID case and passphrase capitalization must match exactly.
Lab 2 · Configure DHCP on a Wireless Router (11.2.3)Rehearse in simulatorPT activity

Scenario: three PCs must obtain addresses automatically. Observe defaults, move the router to 192.168.5.1, reshape the pool, verify with ipconfig and pings.

  • Part 1 · Add 3 PCs; connect each with straight-through cables to Ethernet ports; wait for green links.
  • Part 2 · PC0 → DHCP; record the default gateway (question answer: 192.168.0.1); browse to it, admin/admin; note DHCP enabled, start 192.168.0.100.
  • Part 3 · Router IP → 192.168.5.1 → Save (error page is expected); renew PC0 (Static→DHCP); re-open GUI at 192.168.5.1.
  • Part 4 · Start IP → 192.168.5.126; Max Users → 75 → Save; renew PC0; ipconfig (question answer: PC0 = 192.168.5.126).
  • Part 5 · Enable DHCP on PC1 (= .127) and PC2 (= .128).
  • Part 6 · From PC2: ping 192.168.5.1, ping 192.168.5.126, ping 192.168.5.127 — all successful.
Model answers & gotchas
  • Changing the router IP makes the DHCP start address auto-follow to the same network (then you edit it to .126).
  • Leases are sequential from the start address: .126, .127, .128 for PC0–PC2.
  • A client only sees the new pool after renewing its lease.
Lab 3 · Identify MAC and IP Addresses (13.1.3)Rehearse in simulatorPT activity

Scenario: in Simulation mode, capture PDUs hop-by-hop for a local ping (172.16.31.3 → 172.16.31.2) and a remote ping (→ 10.10.10.2), recording Src/Dst MAC + Src/Dst IPv4 at every device, inbound and outbound.

  • Part 1 · Realtime: ping 172.16.31.2 from 172.16.31.3 works; then Simulation mode and repeat; open the PDU.
  • Part 1 · Record step 1: Src MAC 0060.7036.2849, Dst MAC 000C.85CC.1DA7, Src IP 172.16.31.3, Dst IP 172.16.31.2; Capture/Forward until delivered; inbound PDU unchanged.
  • Part 2 · ping 10.10.10.2; first PDU’s Dst MAC = 00D0.BA8E.741A — the router’s G0/0 interface (the gateway), while Dst IP stays 10.10.10.2.
  • Part 2 · Capture/Forward through the router; record both inbound and outbound PDUs at the router — MACs change, IPs don’t.
  • Part 2 · Repeat for the echo reply from 10.10.10.2; complete the table; answer the 15 reflection questions.
Reflection model answers
  • 1) Copper straight-through cables and wireless (AP) links. 2) No — media never change PDU handling. 3–4) The AP just converts the frame to radio; no addressing changes. 5) Layer 2. 6) Cables & APs: Layers 1–2.
  • 7) Destination MAC appears first in the header. 8) Red X = failed/dropped PDU; green check = successful. 9) MACs changed at the router. 10) 00D0.BA… = the router’s interfaces. 11) The others = end hosts (PCs, server).
  • 12) IPv4 addresses never changed. 13) In the pong, source and destination swap. 14) A router must sit on a different network per interface to route between them. 15) 172.16.31.0/24 and 10.10.10.0/24.
Lab 4 · Examine NAT on a Wireless RouterRehearse in simulatorPT activity

Scenario: inspect the router’s public (ISP) address vs its private LAN, put 4 PCs on DHCP, then in Simulation mode watch periodic HTTP PDUs cross the router and compare inbound vs outbound headers.

  • Part 1 · PC + DHCP; browse to the gateway (admin/admin); Status → Router → Internet connection IP. Question answer: public address.
  • Part 2 · Status → Local Network: internal address + DHCP range. Question answer: private addresses.
  • Part 3 · Add 3 more PCs, DHCP on all; ipconfig /all shows private addresses — these cannot cross the internet, so NAT must translate.
  • Part 4 · Simulation mode; filter to TCP+HTTP; Complex PDU: HTTP, source port 1000, destination ciscolearn.nat.com, Periodic 120 s; Play.
  • Part 5 · Open event envelopes; compare Inbound vs Outbound PDU tabs — the SRC IP changes at the router (private → public). Check Results.
Model answers & gotchas
  • Internet-port address = public (ISP-assigned); LAN + DHCP pool = private (192.168.0.0/24).
  • Outgoing: source private IP:port is rewritten to the router’s public IP with a unique port; the reply to that port is translated back to the right PC — that mapping is the NAT table.
